What this app is standing on

Everything below runs against your knowledge graph. Some of it is stored data — your ratings, your subscriptions. Some of it is virtual: labels and relationships that don't exist as rows anywhere, but are generated on demand when a query traverses them. To Cypher they look identical. Your per-user scope is injected by the server, which is why no query below mentions a user id.
All queries run through gateway.kg.query

Stored — your own records

Films you've rated

A plain traversal. Every rating hangs off you and points at a Movie whose metadata came from OMDb. The $q = '' guard lets one query serve both the unfiltered list and the search box.
MATCH (me:AssistantUser)-[:RATED]->(rt:MovieRating)-[:OF]->(m:Movie)
WHERE $q = ''
   OR toLower(m.title)    CONTAINS toLower($q)
   OR toLower(m.director) CONTAINS toLower($q)
RETURN m.title AS title, m.year AS year, m.director AS director,
       m.genre AS genre, m.imdbId AS imdbId, m.poster AS poster,
       m.plot AS plot, rt.rating AS rating
ORDER BY rt.rating DESC, m.title ASC
LIMIT 200

Adding or changing a rating

The rating popup resolves a title through OMDb, then creates a MovieRating using your id and the film's IMDb id as its stable key. Saving the same film again updates that record. The repository anchors it to you with RATED; the OF hop to full film metadata remains virtual.
gateway.repository.createEntry({
  type: 'MovieRating',
  data: {
    ratingKey: myId + '::' + imdbId,
    raterId: myId, imdbId, title, rating,
    notes, watchedOn
  }
})

Everything you've already seen

Loaded once at startup into a set of IMDb ids and normalised titles. Every recommendation and every "More like this" result is filtered against it, so nothing you've rated can come back as a suggestion.
MATCH (me:AssistantUser)-[:RATED]->(rt:MovieRating)-[:OF]->(m:Movie)
RETURN m.imdbId AS imdbId, m.title AS title
LIMIT 1000

Your streaming subscriptions

Also loaded at startup, then used to mark services yours in the Where-to-watch panel.
MATCH (me:AssistantUser)-[:SUBSCRIBES_TO]->(s:UserStreamingSubscription)
RETURN s.serviceId AS id, s.serviceName AS name
LIMIT 50

Virtual — generated on traversal

Your taste portrait

There is no stored summary node. Following HAS_MOVIE_TASTE_SUMMARY reads across all your ratings and composes the portrait at query time, then caches it.
MATCH (me:AssistantUser)-[:HAS_MOVIE_TASTE_SUMMARY]->(ts:MovieTasteSummary)
RETURN ts.summary AS summary, ts.count AS count

Films like… / More like this (saved view)

A parameterised virtual view, and the same one behind both the Discover search box and the per-card button. The properties in the braces aren't filters over existing nodes — they're arguments. The Adventurousness slider is passed straight in as steer, which is why the same title returns different films at Safe and at Radical.
MATCH (x:MoviesLike {
  movie:    $movie,     // the card's own title, or your typed one
  steer:    $steer,     // the slider's prose hint
  minYear:  1900,
  maxYear:  2100
})
RETURN x LIMIT 12
// results then filtered against your seen-set, client side

Chosen for you

A two-stage virtual chain, anchored on your whole taste rather than one film. Following HAS_MOVIE_TASTE_SUMMARY materialises the taste portrait above; following SUGGESTS from it generates films matching the portrait's through-lines. Your typed steer is appended to the slider's hint and flows into the generator as the ai.hint directive.
MATCH (me:AssistantUser)-[:HAS_MOVIE_TASTE_SUMMARY]->(ts:MovieTasteSummary)
MATCH (ts)-[:SUGGESTS {ai: {hint: $steer}}]->(m:Movie)
WHERE NOT EXISTS { (me)-[:RATED]->(seen:MovieRating)
                   WHERE seen.imdbId = m.imdbId }
RETURN DISTINCT m LIMIT 12

New & now (saved view)

The same taste chain over a different edge — SUGGESTS_NEW — whose producer is web-grounded: what's newly in cinemas or fresh on streaming isn't something a model can recall, so it searches the live web, then resolves each find through OMDb before it becomes a Movie node here.
MATCH (x:NewReleases {
  steer:    $steer      // slider hint + your own words
})
RETURN x LIMIT 12
A note on cost
The virtual traversals are the slow ones — several seconds, because something is genuinely reasoning over your ratings each time rather than reading an index. The taste summary and every generated edge are cached (the summary weekly, new releases daily), which is why repeats come back fast.

Off the graph

Four of the card buttons reach outside the knowledge graph entirely, through the typed gateway:
gateway.streamingAvailability.getShow({ id: imdbId, country: 'au' })
    → Where to watch, filtered to the Australian catalogue

gateway.brave.webSearch({ q: title + year + ' film review' })
    → then gateway.ai.complete(...) to summarise the consensus

gateway.ai.complete({ prompt: 'concert works matching ...' })
    → then gateway.youtube.searchYouTubeVideos(...) per work

gateway.wikipedia.search(...) → gateway.wikipedia.getSummary(...)
No call in this app talks to an external host directly — every one goes through the gateway, which holds the credentials and does the fetching.
